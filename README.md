# Freedom Dialog — Conversation Quality Analytics

Прототип оценивает диалоги по настраиваемому чек-листу, показывает реплики и обоснования, поддерживает апелляции и выгрузку результатов по формату организаторов.

## Локальный запуск (Windows PowerShell)

Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt -r backend\app\services\ai\requirements.txt
```

Сохраните исходный ответ организаторов для DEV в `data/dev_data.json`. Этот файл и ключи исключены из Git. Альтернативно можно задать переменную `CQA_ORGANIZER_API_URL` и загрузить набор через интерфейс по его ID.

В первом окне PowerShell задайте переменные окружения `GROQ_API_KEY` и `GROQ_MODEL=qwen/qwen3.8-27b`, затем запустите сервер:

```powershell
cd backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Во втором окне из корня репозитория создайте начальный чек-лист и запустите интерфейс:

```powershell
cd backend
..\.venv\Scripts\python.exe seed_checklist.py
cd ..\frontend
..\.venv\Scripts\python.exe -m http.server 5500 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:5500`. Через настройки API выберите FastAPI и адрес `http://127.0.0.1:8000`. Также интерфейс доступен по адресу самого сервера `http://127.0.0.1:8000/` и автоматически подключается к API того же сервера. Без сервера интерфейс использует демонстрационные данные; демо-оценки не являются результатами модели.

Оценки сохраняются в локальной SQLite-базе. Пустая база получает начальный официальный чек-лист автоматически. При рассмотрении новой апелляции исходный ответ сохраняется отдельно от решения. При обновлении старой базы приложение добавляет поле для новых апелляций; первоначальная оценка уже рассмотренных старых апелляций, если она ранее не сохранялась, может быть недоступна. На хостинге с временной файловой системой база и загруженные данные могут исчезнуть при перезапуске; для постоянного хранения нужен настроенный постоянный том или внешнее хранилище.

## Выгрузка результатов

Укажите `CQA_TEAM_NAME`, запустите `python backend/run_batch.py --dataset dev` из корня репозитория; для контрольного набора сохраните данные в `data/prod_data.json` и используйте `--dataset prod`. Подробности и повтор ошибочных записей — в [BATCH_EXPORT_README.md](BATCH_EXPORT_README.md).

`results/dev/results.json` содержит подготовленные результаты DEV. Данные PROD появляются только после выдачи организаторами; не подменяйте их синтетическими оценками. Наличие 65 результатов не означает 100% точности.

## Модель и примерная стоимость

Для внешнего API используется `qwen/qwen3.8-27b` через Groq. По [тарифу Groq](https://console.groq.com/docs/model/qwen/qwen3.8-27b) на 8 ноября 2026 года: $0,80 за миллион входных и $4,00 за миллион выходных токенов. В полном прогоне 65 DEV-диалогов потреблено 208 864 входных и 30 774 выходных токена: ориентировочно **$0,00446 за диалог**, или $0,2902 за весь набор по опубликованному платному тарифу. В этом прогоне было 65 попыток и не было повторов. Длинные транскрипты и повторные вызовы могут стоить больше; фактическая стоимость зависит от тарифа и всех вызовов.

## Локальная проверка без запросов к Groq

После сохранения DEV-данных:

```powershell
cd backend
..\.venv\Scripts\python.exe -m unittest test_workflow_offline.py test_evidence_export.py test_dev_delivery.py
```

Тестовый сценарий оценки использует имитацию модели и временную базу; он проверяет структуру, но не точность AI. Для проверки интерфейса на другом компьютере нужен доступный HTTPS-сервер FastAPI: локальный адрес доступен только на том же компьютере.
